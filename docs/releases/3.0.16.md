# KetchupE 3.0.16

Windows 일일자금일보 출력 후 Excel이 정상 종료됐는데도 실패로 표시될 수 있는 문제를 수정했다. 이 수정에는 Excel 재설치, 권한 변경 또는 LibreOffice 설치가 필요하지 않다.

## 오류 원인과 수정

출력 뒤 정리 스크립트가 이미 종료된 Excel 프로세스를 조회하면 PowerShell은 오류 텍스트 없이 종료 코드 1을 반환할 수 있었다. 앱은 이를 Excel 출력 실패로 판정하고 LibreOffice로 전환했다. LibreOffice가 없으면 두 엔진이 모두 실패한 것으로 표시됐다.

- 이미 종료된 Excel은 정리 성공으로 처리한다. 실행 중인 프로세스를 종료할 때는 기존의 프로세스 이름·ID·시작 시각 검증을 유지한다.
- Excel의 실제 오류와 정리 오류가 함께 발생하면 원래 Excel 오류를 보존한다.
- PowerShell 진행 상태 XML을 사용자에게 노출하지 않는다. 파일 열기·재계산·설명 영역 측정·저장·PDF 출력 등의 실패 단계와 오류번호 또는 시간 초과를 표시한다.
- 실제 원인과 무관하게 설치·활성화·권한을 확인하도록 안내하던 공통 오류 문구를 제거한다.

## 검증과 한계

로컬 PowerShell에서 기존 정리 스크립트의 종료 코드 1을 재현했고 수정 후 0을 확인했다. 회귀 테스트는 원래 오류 보존, 시간 초과·단계 표시, 스크립트 소스 비노출을 검증한다. Windows CI에서는 Office 없이 실제 Windows PowerShell로 이미 종료된 프로세스의 정리와 다른 프로세스 보호를 검사한다.

이 수정은 확인된 앱 버그를 해결한다. 해당 사용자 PC에서 Excel의 실제 파일 저장·PDF 출력까지 성공하는지는 업데이트 후 확인해야 한다. 다른 Excel 오류가 있으면 수정된 메시지로 실패 단계와 원인을 확인할 수 있다.
