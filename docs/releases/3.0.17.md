# KetchupE 3.0.17

에이전트 화면 오른쪽 상단에 현재 빌드의 앱 버전을 표시한다. 번호는 package.json에서 읽으므로 태그 빌드와 개발 빌드가 각각 실제 패키지 버전을 표시한다.

## Mac Excel 출력 수정

- 재계산된 임시 XLSX를 저장할 때 기존 파일 교체 확인창이 자동화를 막아 시간 초과가 발생할 수 있었다. 작업 중 Excel 알림을 억제하고 성공·실패 경로에서 원래 설정을 복구한다.
- 열린 문서가 없으면 첫 XLSX의 계산 설정이 앱의 수동 계산 모드를 덮어써 PDF 출력 전에 RAND 같은 수식을 다시 계산할 수 있었다. 임시 통합문서를 먼저 열어 수동 계산 모드를 고정하고 대상 파일을 연 뒤 임시 문서를 닫는다. Windows의 기존 임시 통합문서 방식은 유지한다.
- Mac Excel의 worksheet Save As PDF는 다른 보이는 시트까지 출력했다. PDF 출력 중에만 작업 통합문서의 다른 워크시트를 숨기고 저장하지 않고 닫는다. 최종 XLSX의 시트·서식·수식·표시 상태는 그대로 유지한다.
- 자동화 설정, 파일 열기, 시트 선택, 계산, 저장, PDF 출력의 오류 단계를 구분한다. 파일 열기가 정상 통합문서를 반환하지 못해도 정리 오류가 최초 오류를 덮어쓰지 않도록 한다.

- Excel이 빈 셀과 빈 문자열의 저장 표현을 바꾸어도 입력 변경으로 오판하지 않는다. 최종 원본 셀 XML은 유지하며, 실제 문자나 공백의 삭제는 계속 거부한다.

## 검증

실제 Excel을 사용하는 선택적 통합 테스트를 추가했다. 대상 시트와 인쇄 영역만 PDF에 포함되는지, 재계산과 휘발성 수식의 최종 캐시가 유지되는지, 긴 설명이 병합 영역에서 잘리지 않게 보정되는지, 글꼴과 짧은 행이 유지되는지, PDF 출력이 최종 XLSX 파일을 변경하지 않는지 검사한다. Mac에서는 성공 및 잘못된 시트 이름으로 실패한 뒤에도 Excel 설정이 복구되는지 검사한다.

실행: `KETCHUPE_TEST_EXCEL=1 npx vitest run electron/business/dailyCash/nativeExcel.integration.test.ts`. 활성화된 데스크톱 Excel이 필요하며 다른 Excel 자동화와 동시에 실행하지 않는다. 일반 CI에서는 이 테스트를 건너뛴다.

Windows COM 실출력과 사용자 PC별 Office 상태는 Mac 검증으로 보장할 수 없다. 서명된 macOS 배포에는 기존 CI 서명 인증서 설정이 필요하다.

로컬 Mac Excel 16.114.4에서 두 통합 테스트가 통과했다. 일반 테스트 391개, AgentPage 화면 테스트 15개, TypeScript 검사 및 프로덕션 빌드도 통과했다. 기존 10월 비교용 파일은 원본 과거 시트에 외부 링크 구성 없이 `[1]` 참조가 남아 있고 Excel이 내용 복구를 요구했다. 이 파일의 완전한 Excel 출력 성공은 확인하지 못했으며, 수식을 삭제하거나 참조 대상을 추측해 복구하지 않았다.

정상 일보 fixture를 실제 업무 실행기로 생성하고 Excel 재계산 → 최종 XLSX → PNG까지 완료했다. 출력 엔진이 Excel임을 명시적으로 검사했고, 계좌별 증감·집행 잔액·원화 합계·만기 대사 5개 항목이 통과했다. 이는 테스트 데이터 결과이며 기존 10월 실자료의 복구 성공을 의미하지 않는다.
