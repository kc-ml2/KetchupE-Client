# 일일자금일보: 보존할 수식과 입력할 값

새 일보는 이전 일보 시트를 복사한 뒤 **원천값·확인된 거래만 입력하고, 합계·증감 연결·환산·마감 계산은 Excel 수식으로 유지한다.** 수식 셀에 저장된 계산 결과가 있더라도 수식을 없애고 그 숫자만 입력하지 않는다. LLM은 작업을 연결하며, 원천 추출·검증은 코드가, 최종 수식 재계산은 Excel 또는 LibreOffice가 수행한다.

이 문서의 셀 주소는 참고 파일 `261013_일일자금일보.xlsx`의 `261013` 시트 기준이다. **정기예금 행이 추가·삭제되면 아래쪽 주소도 바뀐다.** 실제 생성에서는 [report.ts](report.ts)의 `layout()`으로 구역 제목·합계·기초금액·마감잔액을 찾아야 한다. 예제 주소를 다른 양식에 그대로 고정하지 않는다.

## 요청사항별 구현·검증 기준

| 요청사항 | 현재 구현 및 자동 테스트의 확인 대상 |
| --- | --- |
| 1. 수식 유지 | 소계·원화합계·잔액·환산 수식을 유지한다. 단기성 원화 증가·감소는 당일 거래의 계좌 연결과 실제 입력 셀에 맞춰 `SUM` 참조를 갱신한다. 거래 순서 변경과 기존 계좌별 행 구간 초과를 검사한다. |
| 2. 숫자 우측 정렬 | 금액·환율 숫자 셀에 우측 정렬을 적용하고 저장 후 서식을 검사한다. |
| 3. 없는 금액은 0 | 금액 입력 영역의 빈 값·없음을 뜻하는 하이픈은 숫자 `0`, 표시 형식은 `#,##0;-#,##0;0`으로 통일한다. 미확인 수식 결과는 별도 확인한다. |
| 4. 최초고시 환율 | 하나은행에 `pbldDvCd=1`, `pbldSqn=1`로 최초고시 1회차를 요청하고 응답 회차도 검증한다. 최종고시 캐시는 재사용하지 않는다. 모의 요청·응답 테스트와 브라우저 실서버 조회·응답 파싱으로 확인했다. 검증 범위는 아래 기록을 참고한다. |
| 5. 금액 반올림 | 후속 요청에 따라 버림을 **반올림**으로 변경했다. 입력 금액과 `ROUND(금액,0)` 수식은 같은 기준을 쓰고, 환율 정밀도는 유지한다. 양수·음수·0.5 경계를 검사한다. |
| 6. 집행 설명 한 줄 | 집행 상세행의 설명·금액은 맑은 고딕 11pt로 통일한다. 개행은 공백으로 바꾸고 `wrapText: false`, `shrinkToFit: false`를 적용한다. 열 너비는 유지하며 긴 설명은 화면에서 잘려도 전체 텍스트를 셀에 보존한다. |
| 7. 전일 예정내역 포함 | 주간계획과 전일 일보의 해당 날짜 예정내역을 합쳐 실적 확인표에 넣고, 중복은 일대일로 제거한다. 실제 집행 여부·금액은 담당자 확인 후 KC와 대사한다. |
| 8. 기준일 자동 처리 | 작업일 전날(주말·등록된 공휴일이면 직전 영업일)을 일보·KC 기준일로 자동 적용한다고 시작 화면에서 안내한다. 별도 기준일 입력·확인 질문은 없다. KC 파일명에 날짜가 없어도 완료까지 진행하며, 명시된 날짜가 다를 때만 오류로 처리한다. 이전 `statusDate` 답변은 사용하지 않는다. |

자금대체의 거래처는 **현재 내역의 출발·도착 및 연동계좌 설명**으로 판단한다. 특정 우리은행 계좌번호나 특정 증권사 이름을 고정 목적지로 쓰지 않는다. 아래 계좌 연결 규칙과 자동 테스트는 같은 번호·다른 설명, 다른 번호·같은 설명, 연동 설명 없음·충돌, 반대 방향 이체를 포함한다.

사용자의 로컬 실행으로 실제 Excel 재계산·출력과 50개 계좌 대사가 완료된 결과를 확인했다. 이후 수정한 글꼴·PNG 취소선 처리는 별도 검증 대상이다. 하나은행은 브라우저 실서버 조회와 실제 응답 일부의 앱 파싱을 확인했으며, 앱의 직접 POST 실행 검증은 남아 있다.

## 1. 보존할 수식

### 자산 본표와 소계

아래 표의 `r`은 해당 자산의 상세행을 뜻한다. 소계·합계행은 상세행과 구분한다.

| 구역 / 셀 예시 | 보존할 수식 / 의미 | 처리 기준 |
| --- | --- | --- |
| 본표 금일금액 `Hr` | `=Dr+Er-Gr` | 단기성 현금, 받을어음, 적금, 정기예금, 신탁 모두 전일+증가−감소 관계를 유지한다. KC 잔고는 대사 기준이며 `H` 수식을 숫자로 대체하지 않는다. |
| 단기성 원화 증가 `E10`, `E11` | 원본 예: `=SUM(D126:D131)`, `=SUM(D132)` | 계좌별 입금 합계 수식을 유지하고, 이번에 입력한 해당 계좌의 거래 셀로 참조를 갱신한다. |
| 단기성 원화 감소 `G10`, `G11` | 원본 예: `=SUM(D152:D169)`, `=SUM(D170)` | 계좌별 지급 합계 수식을 유지하고, 이번에 입력한 해당 계좌의 거래 셀로 참조를 갱신한다. |
| 원화 소계 `D14/E14/G14/H14`, `D16/E16/G16/H16` | 예: `D14=SUM(D10:D13)`, `E14=SUM(E10:F13)` | 원본의 `SUM`과 병합 셀을 포함한 참조 범위를 유지한다. |
| 단기성 원화 합계 `D17/E17/G17/H17` | 예: `D17=D9+D14+D16`, `H17=H9+H14+H16` | 현금·보통예금·수익형 증권 소계를 연결한다. |
| 외화 통화별 소계 22·25·27·29·31행 | `D/E/G/H/I`의 해당 통화 상세행 합계 | 통화를 섞지 않는다. **CNY 27행은 26행만 참조**하도록 한다. 참고 양식의 JPY까지 포함하는 잘못된 CNY 참조는 복제하지 않는다. |
| 받을어음 42행, 적금 47행 | 해당 구역의 `D/E/G/H` 합계 | 기존 합계 수식을 유지한다. |
| 원화 정기예금 96행 | 예: `D96=SUM(D51:D95)`, `H96=SUM(H51:H95)` | 현재 양식의 전체 예금 상세행을 합산한다. |
| 외화 정기예금 115행 | 예: `D115=SUM(D100:D114)`, `I115=SUM(I100:I114)` | `D/E/G/H/I` 합계 및 기존 `L/M` 합계 수식을 유지한다. |
| 신탁 121행 | 예: `D121=SUM(D119:D120)`, `H121=D121+E121-G121` | 원본의 합계·잔액 수식을 유지한다. |

**보존 대상은 계산 관계와 합계 수식이며, 과거 거래의 행 번호가 아니다.** 단기성 원화 계좌의 `E/G`는 해당 계좌에 연결된 당일 실적 금액 셀을 더하는 `SUM`으로 작성한다. 예를 들어 첫 계좌의 입금이 `D126`, `D128`에 있으면 `=SUM(D126,D128)`, 다른 계좌가 `D127`에 있으면 `=SUM(D127)`이다. 거래가 없으면 `=SUM(0)`이다. 원본에 수식이 없던 삼성증권 등의 계좌도 같은 규칙을 쓴다. 외화·정기예금 등 나머지 상세행은 기존 수식이 있으면 보존하고, 없으면 확인된 입출금 값을 입력한다. 계좌별 고정 행 구간 없이 집행 구역 전체의 빈 행을 사용한다. 구역 전체를 넘는 건수는 양식 확장이 필요하다.

### 외화 환율·환산

| 셀 예시 | 수식 / 값의 역할 | 처리 기준 |
| --- | --- | --- |
| 외화 상세행 `Jr` | 장부환율 `=Ir/Hr` | 수식을 유지하고 잔고 0의 나눗셈은 `=IFERROR(Ir/Hr,0)`으로 처리한다. 환율 소수점은 유지한다. |
| `K24`, `K28`, `K30`, 외화 정기예금 `Kr` | 예: `=K23`, `=K21`, `=$K$21` | 다른 환율 셀을 참조하는 수식은 유지한다. 최초고시를 반복해서 숫자로 덮어쓰지 않는다. |
| 외화 상세행 `Lr` | 매매기준금액 `=Hr*Kr` 또는 `=Kr*Hr` | 원본 계산식을 유지하고 `=ROUND(원본계산식,0)`으로 금액을 정수로 반올림한다. |
| 외화 상세행 `Mr` | 환차 `=Lr-Ir` | 환산금액−장부금액 수식을 유지한다. |
| `M29`, `M31`, `L115`, `M115` | 환차·외화 정기예금의 보조 합계 | 원본에 존재하는 합계 수식을 보존한다. |
| `M98` | `=M19` | 외화 정기예금의 고시 안내도 위쪽 고시 안내를 참조한다. |

**환율 입력 셀**인 `K21`(USD), `K23`(JPY), `K26`(CNY)과 **환율 참조 수식 셀**을 구분한다. 현재 외화 정기예금 구역은 USD만 지원한다.

### 주요 집행내역의 기초·소계·마감

| 셀 | 보존할 수식 | 의미 |
| --- | --- | --- |
| `D125` | `=D17` | 기준일 실적표의 기초금액 |
| `H125` | `=D230` | 작업일 계획표의 기초금액: 기준일 실적 마감잔액 |
| `D151`, `H151` | `=SUM(D126:D150)`, `=SUM(H126:H150)` | 실적·계획 입금 합계 |
| `D229`, `H229` | `=SUM(D152:D228)`, `=SUM(H152:H228)` | 실적·계획 지급 합계 |
| `D230` | `=D125+D151-D229` | 기준일 실적 마감잔액 |
| `H230` | `=H125+H151-H229` | 작업일 계획 반영 후 예상 마감잔액 |
| `D234`, `D235` | `=E17-D151`, `=G17-D229` | 본표 증가·감소와 집행내역 합계 비교 |

이 구역의 `D/H`열도 전체가 입력란은 아니다. **입금·지급 상세행만 입력하고, 위의 기초·합계·마감 셀은 수식으로 둔다.**

### 하단 원화·외화 합계

아래는 참고 양식의 원본 수식이다. 새 시트의 `F`열 합계에는 금액 반올림을 위해 `ROUND(원본계산식,0)`을 적용한다. `G/H`도 수식으로 유지한다.

| 구분 | 외화 환산 합계 `F` | 원화 합계 `G` | 전체 합계 `H` |
| --- | --- | --- | --- |
| 지주 235행 | `=(H22+H29+H31)*$K$21+H25*$K$23+H27*$K$26` | `=H17` | `=F235+G235` |
| 사업 237행 | `=(P235+P236+P232)*$K$21+P234*$K$23+P233*K26` | `=P237+P238+P239+P240+P241+P242` | `=F237+G237` |
| 정기예금 239행 | `=H115*$K$21` | `=H96` | `=F239+G239` |
| 총계 241행 | `=F235+F237+F239` | `=G235+G237+G239` | `=F241+G241` |

특히 **총 원화 `G241`을 코드나 모델이 계산한 상수로 저장하지 않는다.** 위쪽 합계와 KC 보조표가 바뀌면 Excel에서 함께 재계산되어야 한다. 원본에 하단 합계 수식이 없으면 코드가 해당 구역의 셀을 참조하는 수식을 생성한다.

### 조건부로 보존하거나 참조를 갱신할 수식

| 대상 | 보존 / 갱신 조건 |
| --- | --- |
| 본표 전일금액 `Dr`의 과거 시트 참조 | 원본이 같은 행의 과거 `H`를 참조하고, 이전 `H`의 저장 결과를 반올림한 금액이 실제 이월 금액과 일치하면 `=ROUND('직전시트'!Hr,0)`으로 날짜 시트를 갱신한다. 원본에 이월 수식이 없거나 이월 조건을 충족하지 않는 보정 금액을 사용하면 확인된 정수 금액을 입력한다. |
| 외화 장부금액 `Ir`의 계산 수식 | 원본 수식의 저장 결과를 반올림한 금액과 이번에 적용할 장부금액이 같을 때만 수식을 유지하고 `ROUND`를 적용한다. KC 장부금액이 바뀌었거나 저장 결과가 없으면 확인된 입력값을 쓴다. |
| 과거 마감과 현재 기초를 비교하는 검증 수식 | 특정 셀 주소를 가정하지 않고 기초금액 비교식을 찾는다. 참조 대상이 실제 과거 기초·마감 셀인지 확인한 뒤, 직전 시트의 마감잔액을 `ROUND`로 반올림한 값으로 연결한다. 외부 파일·불명확한 참조는 추측하지 않는다. |
| 기타 원본 보조 수식 | 예: `I14=H9+H14`, `P230=P232+P235+P236`. 입력 대상으로 지정하지 않은 보조 수식은 복사·보존한다. |

## 2. 채워 넣을 값

| 입력 대상 | 참고 양식의 위치 | 가져올 내용 / 출처 |
| --- | --- | --- |
| 시트명·보고일 | 새 시트 `YYMMDD`, 제목 `B2` | 작업일 직전 영업일. 주말·등록된 공휴일을 건너뛴다. |
| 실적·계획 날짜 표기 | `A125/A230`, `E125/E230` | 왼쪽은 일보 기준일, 오른쪽은 작업일로 기초·마감 날짜를 갱신한다. |
| 고시 안내 | `M19` | 일보 기준일과 `최초 고시` 문구. `M98`은 이를 수식으로 참조한다. |
| 전일금액 | 본표 상세행의 `D` 중 이월 수식을 유지하지 않는 셀 | 이전 시트 같은 행 `H`의 저장된 금일금액 또는 담당자가 확인한 보정값. |
| 증가·감소 | 단기성 원화를 제외한 본표 상세행 `E/G` 중 원본 수식이 없는 셀 | KC의 입금·출금 또는 담당자가 확인한 계좌별 입출금. 차이를 맞추려고 임의 거래를 만들지 않는다. |
| 예금 만기·신규 가입 | 해당 정기예금 상세행 `E/G`, 신규 행 `A/C` | 만기는 이전 원금을 감소에 반영한다. 신규 가입은 검증된 빈 행에 은행·가입일·만기일·가입 원금을 채운다. 이자는 예금 원금에 합산하지 않는다. |
| 외화 장부금액 | 외화 상세행 `I` 중 수식을 보존하지 않는 셀 | 연결된 KC 계좌의 `기말잔액(장부)` M열. 연결되지 않은 기존 항목은 확인된 이전 장부금액을 이월하고, 만기 처리한 외화 예금은 0으로 정리한다. |
| 기준 환율 | `K21/K23/K26` 및 원본에 환율 참조 수식이 없는 외화 `K` 셀 | 하나은행 기준일 **최초고시 1회차 매매기준율**. JPY는 100엔당 고시를 100으로 나눈 1엔당 값으로 저장한다. 환율 소수점은 버리지 않는다. |
| 기준일 실적 설명 | `B126:B150`, `B152:B228`의 사용 행 | 주간계획의 기준일 지주현금 내역과 전일 일보의 해당 날짜 `금일집행내역(예정)`을 합친 뒤 담당자가 확인한 적요·거래처. |
| 기준일 실적 금액 | `D126:D150`, `D152:D228` | 확인된 실제 입금·지급 금액. 미집행은 0, 누락 거래는 추가한다. |

전일 예정내역은 이전 시트 계획표의 기초 날짜(`E125` 예시)가 이번 일보 기준일과 일치할 때만 가져온다. 설명은 `F/G`, 금액은 `H`의 상세행에서 읽고 합계행은 제외한다. 방향·공백을 정리한 적요/거래처·정수 금액이 같은 거래는 주간계획과 일대일로 중복을 제거한다. 동일 거래가 여러 건이면 남는 건은 유지한다. 계획은 실적의 초안이므로 담당자 확인을 거친다.

### 거래별 계좌 연결과 자금대체

- 실적 확인 후 적요에 있는 계좌번호와 자금대체의 출발·도착 계좌를 사용한다. 입금은 도착 계좌, 지급은 출발 계좌에 연결한다.
- `A에서 B(거래처명 연동계좌) 자금대체` 형식에서는 입금의 도착 쪽, 지급의 출발 쪽 설명을 읽는다. `(삼성증권 연동계좌)`이면 거래처가 정확히 `삼성증권`인 원화 행을, `(키움증권 연동계좌)`이면 `키움증권` 행을 찾는다. `(삼성증권-MMF 연동계좌)`는 별도 `삼성증권-MMF` 행에 연결한다. 공백·전각 문자는 정규화하고 거래처명 전체를 비교한다.
- 예시 `신한557434에서 우리96107116718943(삼성증권 연동계좌) 자금대체`의 입금을 삼성증권 증가에 넣는 근거는 **도착 쪽의 연동계좌 설명**이다. 번호 `96107116718943` 자체에 삼성증권이라는 의미를 부여하지 않는다. 같은 적요의 지급은 출발 계좌에 연결하며, 반대편 거래를 임의로 추가하지 않는다.
- KC 연결은 계좌명에 명시된 `거래처명 연동계좌` 설명 또는 현재 거래 내역에서 KC 계좌코드와 번호가 일치하는 출발·도착 쪽의 설명을 근거로 한다. 사용자 수정·추가·미집행 처리를 반영한 내역을 사용한다. 설명이 없거나 대상 거래처가 없거나 중복·충돌하면 고정 연결하지 않고 기존 계좌 확인 절차를 따른다. 명시적인 담당자 계좌 선택은 그대로 검증해 사용한다.
- 적요만으로 정해지지 않으면 KC 또는 확인된 계좌별 입출금에서 이미 연결된 거래를 제외한 금액을 비교한다. 거래가 들어갈 수 있는 계좌가 하나일 때만 자동 연결한다. 여러 계좌가 가능하면 기존 실적 확인표의 **거래 계좌** 선택란에서 확인한다. 확인된 입출금과 계좌별 실적 합계가 일치해야 진행한다.
- 연동계좌 설명이 있는데 거래처를 유일하게 찾지 못한 경우에는 금액이 맞는 다른 계좌로 자동 우회하지 않고 확인을 받는다.
- 거래별 계좌는 최종 확인과 작업 기록에도 남긴다. 신규·수정 거래, 계좌 선택을 바꾸면 다시 검증한다.

## 3. 입력·서식·검증 공통 규칙

- **금액은 정수:** Excel `ROUND(금액,0)`과 같은 기준으로 반올림한다. 예: `123.4 → 123`, `123.5 → 124`, `-123.5 → -124`. 외화 잔고·장부금액·환산금액도 포함하며 환율 `J/K`는 정밀도를 유지한다.
- **반올림 차이:** KC 원천자료는 반올림 전에 검증한다. 이월 기초와 KC 기초, KC 장부와 계좌잔고가 일치하는데 KC 입출금의 개별 반올림으로 계좌잔고 대사가 어긋나거나, 계좌별 잔고 반올림 합계와 KC 총액 반올림 값이 달라지면 반올림 차이라고 명시하고 발행을 중단한다. 차이를 맞추기 위한 가상 거래를 만들거나 실제 거래금액의 수정을 요구하지 않는다.
- **숫자는 우측 정렬:** 금액 표시 형식은 `#,##0;-#,##0;0`. 금액이 없는 입력 셀은 숫자 `0`으로 채우고 하이픈으로 표시하지 않는다. 설명·구분 등의 빈 텍스트 셀까지 0으로 채우지는 않는다.
- **미확인 금액은 0이 아님:** 원천 수식에 저장 결과가 없는 경우 재계산·저장 또는 담당자 확인이 필요하다. 실제 빈 셀·없음을 나타내는 하이픈과 구분한다.
- **집행 설명은 한 줄:** 집행 상세행의 설명·금액 글꼴은 맑은 고딕 11pt, 행 높이는 최소 18pt로 통일한다. 개행을 공백으로 바꾸고 자동 줄바꿈과 글자 자동 축소를 끈다. 사용자가 긴 설명의 잘림을 허용했으므로 열 너비를 늘리거나 텍스트를 삭제하지 않는다. 제목·예금 조건 등 다른 영역의 서식은 유지한다.
- **기준일은 자동:** KC 파일명에 날짜가 없으면 일보 기준일을 사용하고 따로 묻지 않는다. 파일명에 명시된 날짜가 다르면 오류로 중단한다.
- **기존 자료 보존:** 과거 시트, 입력 대상이 아닌 구분·계좌명·예금 조건, 병합·테두리를 유지한다. 글꼴·행 높이는 집행 상세행의 위 서식 변경을 제외하고 유지한다. 받을어음·적금·신탁은 변동 없음 확인을 전제로 이월한다.
- **재계산 후 대사:** 본표 계좌잔고, 계좌별 증가·감소·외화 장부금액, 주요 집행 마감잔액, 총 원화를 확인한다. 수식 오류·잘못된 참조·원천금액 불일치는 계산값 붙여넣기로 우회하지 않는다.

수식이 있는 셀에 캐시 값(`result`)을 함께 저장하는 것은 미리보기·사전 대사를 위한 것이다. 최종 XLSX에는 수식이 남아야 하고, 출력 엔진이 재계산한 결과로 다시 검증해야 한다. 계좌별 집행 합계 수식은 확인된 거래 연결로 생성한다. 이미 삭제된 기타 검증 수식은 값만 보고 복원하지 않으므로 정상 원본 양식이 필요하다.

**PNG의 수식 값 취소선 방지:** Excel이 수동 계산 상태의 수식을 미계산 값으로 표시하지 않도록, PDF를 출력할 때만 임시 복사본의 해당 시트 수식을 최종 XLSX의 검증된 저장 결과로 바꾼다. 숫자·0·날짜·참/거짓·문자열을 보존하며 저장 결과가 없거나 오류이면 출력하지 않는다. 이 임시 복사본은 출력 후 삭제하고, 사용자에게 전달하는 XLSX의 수식·원본 서식은 유지한다.

**PNG 화질:** Excel에서 출력한 PDF를 PDFium으로 **300dpi** 렌더링하고 무손실 PNG로 저장한다. 기존 144dpi PNG를 확대하는 방식이 아니며, PNG에도 300dpi 정보를 기록한다. A4 세로 한 페이지는 약 2,479×3,508픽셀이다. 여러 페이지는 세로로 연결하고 기존 9,600만 픽셀·출력 파일 20MiB 제한은 유지한다. 화면에 맞춰 축소한 미리보기보다 원본 PNG를 확대해서 볼 때 차이가 뚜렷하다.

2026-11-13에 [하나은행 환율 페이지](https://www.kebhana.com/cont/mall/mall15/mall1501/index.jsp)의 조회 양식에서 **‘최초’ 선택값이 `pbldDvCd=1`**임을 확인했다. 브라우저로 `hana.ts`와 같은 조회 주소·날짜 파라미터를 사용해 2026-10-13을 조회했으며 두 응답 모두 HTTP 200이었다.

브라우저 도구가 반환한 HTML 일부(고시 정보와 USD·JPY·CNY의 완전한 행 포함)를 실제 `parseHana()`에 넣어 기준일·1회차·고시시각과 `USD=1335.8`, `JPY=8.423`(1엔당), `CNY=199.34`를 검증했다. 변경 전 조회의 실제 1075회차 응답은 ‘최초고시가 아님’ 오류로 거부되었다. 별도의 자동 테스트는 요청 파라미터, 최초고시 파싱, 최종고시 캐시 폐기, 수동 환율 입력 경로를 확인한다.

**검증 범위:** 실서버 조회는 브라우저 GET으로 수행했고, 앱은 POST를 사용한다. 셸 직접 조회는 DNS 실패와 자동 승인 검토 도구의 설정 오류로 실행을 완료하지 못했으므로 앱 POST부터 완료까지의 통합 검증으로 보지는 않는다. 응답 전체를 보관한 회귀 픽스처 검증도 아니다.

## 5. 실제 자료 실행 검증 진행 상태

2026-11-13에 사용자가 확인한 조합인 **10월 13일 일보를 이월해 10월 14일 기준 일보 생성**을 실행했다. 작업일은 10월 15일이며, 입력은 `261013_일일자금일보.xlsx`, `261014_자금현황표[KC].xlsx`, `주간자금계획서_1009.xlsx`이다. 기존 `261014_일일자금일보.xlsx`의 실적·계획 수정값을 검증 입력의 근거로 사용했다. 원본 파일은 수정하지 않았다.

- 실제 `dailyCashTool.execute()`에서 50개 계좌 연결·입출금·원화 합계 대사를 통과하고 최종 확인 단계까지 도달했다. 동일한 생성 함수로 검증용 시트도 만들었다.
- 하나은행 10월 14일 최초고시는 **08:24:33 · 1회차**, USD `1340.5`, JPY 1엔당 `8.4657`, CNY `200.23`으로 확인했다. 직접 POST 두 번은 네트워크 제한으로 실패해, 브라우저에서 확인한 값을 앱의 수동 환율 입력 경로에 넣었다. 자동 조회 성공으로 기록하지 않는다.
- 실제 Microsoft Excel 앱이 실행 중임을 확인했다. 자동화 검증은 Excel 임시 폴더 쓰기의 `EPERM`으로 중단되었고, 허용된 작업 폴더의 복사본으로 호출한 네이티브 내보내기도 제한된 실행 환경에서 Excel 애플리케이션을 찾지 못했다(`-1728`).
- 권한 확장 실행은 자동 승인 검토 도구의 `Invalid model name: codex-auto-review` 설정 오류로 실행되지 않았다. 이후 사용자가 로컬에서 실행한 14:38 결과로 **실제 Excel 재계산·저장, 50개 계좌 대사, PDF·PNG 생성 완료**를 확인했다. 생성된 PNG에서 집행 설명의 과도한 축소와 수식 값의 취소선을 확인해 위 글꼴·출력용 복사본 처리를 추가했다. 이 후속 수정의 실제 Excel 출력 재검증은 별도로 남아 있다.
